# Mastodonリストタイムラインメディアフィルター機能実装レポート

## 概要

Mastodonのリストタイムラインにメディア付き投稿のみを表示するフィルター機能を実装し、本番環境での問題を解決した実装・調査レポート。

## 実装内容

### 1. バックエンド実装

#### ListFeedモデルの拡張 (`app/models/list_feed.rb`)

```ruby
# frozen_string_literal: true

class ListFeed < Feed
  def initialize(list, options = {})
    @list = list
    @options = options
    super(:list, list.id)
  end

  def get(limit, max_id = nil, since_id = nil, min_id = nil)
    limit    = limit.to_i
    max_id   = max_id.to_i if max_id.present?
    since_id = since_id.to_i if since_id.present?
    min_id   = min_id.to_i if min_id.present?

    if media_only?
      # Get more IDs from Redis since we'll filter some out
      unhydrated_ids = from_redis_ids(limit * 3, max_id, since_id, min_id)

      # Filter to only statuses with media attachments and preserve order
      status_ids_with_media = Status.where(id: unhydrated_ids)
                                     .joins(:media_attachments)
                                     .group('statuses.id')
                                     .pluck(:id)

      # Return statuses in the correct order, limited
      filtered_ids = unhydrated_ids.select { |id| status_ids_with_media.include?(id) }.take(limit)
      Status.where(id: filtered_ids).index_by(&:id).values_at(*filtered_ids).compact
    else
      from_redis(limit, max_id, since_id, min_id)
    end
  end

  protected

  def from_redis_ids(limit, max_id, since_id, min_id)
    max_id = '+inf' if max_id.blank?
    if min_id.blank?
      since_id = '-inf' if since_id.blank?
      redis.zrevrangebyscore(key, "(#{max_id}", "(#{since_id}", limit: [0, limit], with_scores: true).map { |id| id.first.to_i }
    else
      redis.zrangebyscore(key, "(#{min_id}", "(#{max_id}", limit: [0, limit], with_scores: true).map { |id| id.first.to_i }
    end
  end

  private

  attr_reader :options

  def media_only?
    options[:only_media]
  end
end
```

**主要な変更点:**

- メディアフィルター時にRedisから多めにIDを取得（フィルタリングで減ることを想定）
- メディア付きステータスのIDを抽出
- 元の順序を保持しながらフィルタリング

**streaming.js:**

```javascript
export const connectListStream = (listId, { onlyMedia } = {}) => {
  const acceptFunction = onlyMedia
    ? (status) => {
        return status.media_attachments && status.media_attachments.length > 0;
      }
    : null;

  return connectTimelineStream(
    `list:${listId}${onlyMedia ? ':media' : ''}`,
    'list',
    { list: listId },
    {
      fillGaps: () => fillListTimelineGaps(listId, { onlyMedia }),
      accept: acceptFunction,
    },
  );
};
```

## 発生した問題と解決

### 1. 開発環境でのStreaming API接続問題

**問題:** WebSocketが間違ったURL（`ws://localhost:3000/packs-dev/`）に接続していた

**解決策:**

```bash
# .env.developmentに追加
STREAMING_API_BASE_URL=http://localhost:4000
```

### 2. 開発環境でのデータベース接続問題

**問題:** Streaming APIがPostgreSQLに接続できない

**解決策:**

```bash
# .envファイルに必要な設定を追加
DB_HOST=localhost
DB_USER=mastodon
DB_NAME=mastodon_production
DB_PASS=mastodon
DB_PORT=5432
```

### 3. 本番環境でのSSL証明書エラー

**問題:** `self-signed certificate in certificate chain`エラー

**調査結果:**

- Streaming APIの`database.js`は`env.DB_SSLMODE`のみサポート
- `env.DB_SSLROOTCERT`には対応していない
- SSL設定は以下の3つのモードのみ:
  - `disable`: SSL無効
  - `no-verify`: SSL有効、証明書検証なし
  - その他: SSL有効、デフォルト証明書検証

**試行した解決策:**

1. **no-verifyモード** ✅

   ```bash
   DB_SSLMODE=no-verify
   ```

2. **システムレベルCA証明書設定** ❌

   ```bash
   sudo cp /home/mastodon/global-bundle.pem /usr/local/share/ca-certificates/rds-ca-cert.crt
   sudo update-ca-certificates
   ```

3. **NODE_EXTRA_CA_CERTS環境変数** ❌
   ```ini
   [Service]
   Environment="NODE_EXTRA_CA_CERTS=/home/mastodon/global-bundle.pem"
   ```

**最終解決:** 証明書ファイルの拡張子修正

- **問題:** ファイル名が`.pemi`になっていた
- **解決:** `.pem`に修正

## 技術的な学び

### 1. ListFeedの実装における課題

**当初の問題:**

```ruby
statuses = from_redis(limit, max_id, since_id, min_id)
statuses = statuses.joins(:media_attachments).group(:id) if media_only?
```

**問題点:**

- `from_redis`が返すActiveRecord::Relationに対してjoinsを適用しても正しく動作しない
- 順序が保持されない

**解決アプローチ:**

1. Redisから多めにIDを取得
2. メディア付きステータスのIDを抽出
3. 元の順序を保持しながらフィルタリング

### 2. Streaming APIでのフィルタリング

**課題:** サーバー側でメディアフィルターに対応していない

**解決:** フロントエンドでaccept関数を使用

```javascript
const acceptFunction = onlyMedia
  ? (status) => {
      return status.media_attachments && status.media_attachments.length > 0;
    }
  : null;
```

### 3. SSL証明書の取り扱い

**学習内容:**

- Node.jsのStreaming APIでのSSL設定の制限
- システムレベルCA証明書とNode.jsの証明書検証の違い
- ファイル拡張子の重要性

## まとめ

この実装により、Mastodonのリストタイムラインでメディア付き投稿のみを閲覧できる機能が実現されました。クリエイターの作品のみを閲覧したいが、政治的な発言やメンタルヘルスに影響する内容は避けたいというユーザーニーズに対応することができます。

技術的には、既存のPublicTimelineやCommunityTimelineのメディアフィルター機能を参考にしつつ、ListFeedの特性（Redisからの投稿ID取得）に適した実装を行いました。また、開発環境と本番環境での各種接続問題を解決する過程で、MastodonのStreaming APIの仕組みやSSL証明書の取り扱いについても深く理解することができました。
